# Сравнительный анализ Git и SVN

### 1. Почему в SVN создание ветки — дорогая операция, а в Git — почти мгновенная?
В SVN ветка создаётся как физическая полная копия всей директории проекта на сервере (занимает место и требует сетевого запроса). В Git ветка — это легковесный 41-байтный указатель (ссылка) на конкретный хеш коммита.

### 2. Что произойдёт, если сервер SVN отключится на день? А если сервер GitHub?
При падении SVN команда полностью парализована: нельзя коммитить, смотреть историю, создавать ветки или сливать код. При отключении GitHub разработчики продолжают полноценно работать локально (Git распределённый): делать коммиты, ветвиться, смотреть логи; блокируется только сетевая синхронизация между участниками.

### 3. Представьте: в компании 200 разработчиков переходят с SVN на Git. С какими тремя главными трудностями они столкнутся?
1. Необходимость перестройки мышления: понимание Staging Area (индекса) и разницы между локальными коммитами и удалённым push.
2. Сложности при работе с историей и ветвлением (rebase vs merge, fast-forward, разрешение конфликтов).
3. Привычка к блокировкам файлов (lock-modify-unlock в SVN) вместо параллельной работы и слияний в Git.
